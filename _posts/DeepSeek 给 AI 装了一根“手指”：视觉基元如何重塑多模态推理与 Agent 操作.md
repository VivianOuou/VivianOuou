## 一、核心痛点：模型能“看见”，但不能“指准”

现阶段主流多模态模型（GPT\-4V、Gemini 等）已具备成熟的图像识别、内容描述能力，但在**精确空间推理**场景中，存在无法规避的底层缺陷。

### 1\.1 传统模型视觉推理流程

以问题 **“集体照中左边第三个人是否戴眼镜？”** 为例，传统模型执行逻辑如下：

1. 图像分块编码，将图片转化为视觉 Token；

2. 通过注意力机制，匹配语义关键词对应的图像区域；

3. 基于概率分布，输出最终判断结果。

整个推理过程是**隐式、概率性**的。模型无法明确标注判定的像素区域，仅依靠注意力分布“主观判断”，没有精准的定位依据。

### 1\.2 传统模型的应用短板

这种模糊性在高精度场景中会形成致命硬伤：

|应用场景|传统模型困境|
|---|---|
|密集计数|物体重叠、密集排布时，易漏数、重复计数|
|左右、远近等相对位置判断容易出错||
|迷宫、线路图无法连续追踪路径||
|同类按钮、无图标控件无法精准定位||

针对以上问题，DeepSeek 提出颠覆性思路：**摒弃语言描述位置，让模型直接指向位置。**

## 二、视觉基元：给 AI 装上一根“手指”

**基元（Primitives）**源自计算机图形学，是描述空间、形状的最小基础单元。DeepSeek 的核心创新：**将模型推理从语言向量空间，迁移到可量化的坐标空间。**

### 2\.1 三大核心视觉基元

|基元类型|核心用途|数据格式示例|
|---|---|---|
|点（Point）|标记单点位置、追踪移动轨迹|`\(x, y\)`|
|框（Box）|圈定物体、对比尺寸位置|`\[x1, y1, x2, y2\]`|
|路径（Path）|记录连续移动、连通轨迹|`\[\(x0,y0\), \(x1,y1\)\.\.\.\]`|

### 2\.2 传统方案 VS 视觉基元方案

#### 传统模型输出（纯自然语言，不可执行）

```plain text
点击右上角的登录按钮
```

#### DeepSeek 视觉基元输出（结构化坐标，可直接执行）

```json
{
  "action": "click",
  "coordinates": [320, 150],
  "verification": "button_visible"
}
```

### 2\.3 视觉基元的核心优势

- **可验证性**：输出结果附带标注框/坐标，可人工核验判定准确性；

- **可回溯性**：完整记录每一步坐标操作，出错可溯源排查；

- **抗幻觉性**：坐标受图像边界约束，无法编造虚假位置。

## 三、三大推理能力：从感知到精准推演

论文将视觉推理划分为三个递进层级，依托视觉基元实现全链路优化，解决传统模型的推理短板。

### 3\.1 计数推理：先框后数，杜绝误差

**传统方式**：全局扫描图像，凭语义概率直接输出数字，误差率高；
**DeepSeek 方式**：标准化流程精准计数。

```python
# 示例：统计图片中的企鹅数量
boxes = model.detect("penguin", image)  # 检测并框选所有企鹅
boxes = nms(boxes)  # 非极大值抑制，去除重叠框
count = len(boxes)  # 统计有效框数量
# 可选：抽样核验框内目标是否为企鹅，二次校验
```

### 3\.2 空间推理：几何计算替代主观语义

针对问题：**“左侧灰色球和右侧紫色球，哪个体积更大？”**，模型摒弃主观判断，用坐标量化计算：

1. 框选灰球：`\[100,200,180,280\]`，计算面积 6400；

2. 框选紫球：`\[300,210,370,270\]`，计算面积 4200；

3. 输出客观结论：灰色球体积更大。

所有空间关系全部转化为坐标运算，彻底摆脱语义模糊性。

### 3\.3 拓扑推理：分步探索复杂连通结构

迷宫、电路图、交叉线条等场景侧重**连通性**，是传统模型的重灾区。

**传统模型**：试图全局理解结构，一次性推演路径，极易卡死出错；
**DeepSeek 模型**：以智能体形式分步探索。

1. 从起点坐标出发，单次输出一个移动点位；

2. 系统判定点位周边环境（墙体/通路）；

3. 基于 DFS 深度优先搜索迭代探索；

4. 最终生成完整路径坐标序列。

```python
# 迷宫通行路径示例
path = [
    (0, 0), (0, 1), (0, 2), 
    (1, 2), (2, 2), ... , (9, 9)
]
```

模型无需理解全局结构，仅依靠局部精准决策，大幅降低复杂拓扑推理难度。

## 四、AI Agent 赋能：从“看懂”到“精准操作”

视觉基元最核心的落地场景是 **AI 自动化智能体（Agent）**，实现电脑、手机界面的无人精准操作。

### 4\.1 传统视觉 Agent 的痛点

主流 GPT\-4V 类 Agent 执行流程：截图→语义描述→指令执行，存在明显缺陷：

- 同名控件过多，无法区分目标按钮；

- 无文字图标、特殊控件难以语言描述；

- 拖拽、滑动等复杂动作指令模糊，执行失败率高。

### 4\.2 视觉基元 Agent 标准化指令

#### ✅ 点击操作

```json
{"action": "click", "coordinates": [320, 450]}
```

#### ✅ 拖拽操作

```json
{
  "action": "drag_and_drop",
  "source": [140, 210],
  "target": [540, 210]
}
```

#### ✅ 滚动操作

```json
{
  "action": "scroll",
  "from": [500, 600],
  "to": [500, 200]
}
```

### 4\.3 错误自愈：可回溯的操作序列

Agent 完整记录每一步操作坐标，形成执行链路，支持错误修复：

```plain text
step1: click [320, 450]   → 执行成功
step2: type "机械键盘"     → 执行成功
step3: click [950, 120]   → 按钮无响应，执行失败
step4: retry [950, 120]   → 二次重试，依旧失败
step5: relocate → [945, 125] → 重新定位，执行成功
```

依托操作序列，智能体可完成**重试、重定位、步骤回退**，大幅提升自动化稳定性。

## 五、性能优化：极低开销的视觉编码架构

精准坐标推理不会带来算力爆炸，DeepSeek 针对性优化了 Token 编码逻辑，兼顾精度与效率。

|性能指标|传统多模态方案|DeepSeek 视觉基元|
|---|---|---|
|800×800图像Token数|数百 \~ 上千个|约90个常驻条目|
|推理方式|全局一次性编码|按需局部查询编码|
|内存占用|高，KV缓存占用大|低，临时Token用完即弃|

### 核心优化技术

- **双阶段编码**：粗编码保留全局信息，精编码聚焦目标局部区域；

- **坐标查询接口**：主动调取指定坐标像素特征，无需加载全图；

- **Token回收机制**：临时推理Token使用后立即释放，不占用缓存。

## 六、技术局限与未来演进方向

### 6\.1 当前明确局限（论文公开说明）

|现存局限|详细说明|
|---|---|
|触发机制单一|需人工提示激活视觉基元，模型无法自主判断调用时机|
|分辨率限制|微小目标、模糊边界物体，坐标标注精度下降|
|拓扑推理短板|超长路径、极度复杂迷宫仍存在推理错误|

### 6\.2 未来迭代方向

- **自主触发机制**：模型自动识别场景，按需启用视觉基元；

- **搜索算法升级**：DFS 迭代为 A\* 算法，提升路径推演效率；

- **3D视觉拓展**：适配点云、三维网格，实现空间立体推理；

- **双通道融合**：结合视觉基元\+语言理解，兼顾精度与语义。
